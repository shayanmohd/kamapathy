# Page actions

Run `node scripts/kamapathy.mjs help` for CLI syntax, and `help <command>` for one command's usage, flags, route and script equivalent. Resolve that path from this skill directory. Commands accept `--json` for compact machine-readable responses; default text omits repeated metadata. `space open`, `space create` and `open` return IDs for subsequent commands. Anywhere a command takes a tab ID, `SPACE_ID:p2` names a page by its label instead.

## Form batches

Pipe a JSON object with an `actions` array, or the array itself, into `batch TAB_ID`. Use a safely written temporary file or structured stdin tool input. Avoid shell interpolation of field values. Do not put sensitive values in command arguments, shell history, or source control.

For an authorized form submission, after observing these example refs on the actual page:

```json
{
  "actions": [
    { "type": "fill", "ref": "@e4", "value": "Avery" },
    { "type": "fill", "ref": "@e5", "value": "avery@example.com" },
    { "type": "click", "ref": "@e7" },
    { "type": "wait", "selector": "#confirmation", "text": "Saved", "timeoutMs": 5000 },
    { "type": "snapshot", "selector": "#confirmation", "maxChars": 1200, "maxControls": 10 }
  ]
}
```

`node scripts/kamapathy.mjs batch TAB_ID` reads that JSON from stdin, which must end within 30 seconds. All actions run sequentially on that tab. A batch may contain 1 to 20 actions and at most 64 KiB of encoded JSON. Every step is checked before the first one runs: a field a step does not define is refused with `400 unknown_field`, which names the field, the allowed fields and the step, and suggests a near miss such as `timeoutMs` for `timeout`. The CLI makes the same check before it connects. Do not guess a future ref inside a batch. A snapshot action's newly returned refs can be used in the next client request. Stable selectors are useful across a known navigation followed by a wait.

Each completed entry has `{index,type,result}`. On failure the response has `ok:false`, `results`, `failedIndex`, and `error`; the CLI exits with status 1 while preserving completed results. The error's `retryable` is true only when the failed step's condition can clear by itself and nothing reached the page, and its `dispatched` is true when the failed step reached the page; both describe that step alone, and `--json` shows them. Indices in JSON are zero-based; text output numbers actions from 1. A failed batch does not roll back prior actions. Continue only after checking which steps actually happened.

## Supported actions

| Type | Fields | Behavior |
| --- | --- | --- |
| `snapshot` | `mode?`, `selector?`, `maxChars?`, `maxControls?`, `scope?`, `root?`, `format?`, `locators?`, `header?`, `cursor?` | Read visible text and controls, optionally scoped to one element, a ref's subtree or the viewport |
| `click` | exactly one of `ref` or `selector`, optional `button`, `clickCount`, `delayMs`, `position`, `force`, `timeoutMs`, `label` | Click one visible, enabled element once its point can take the press; a control drawn with no size is clicked in the page |
| `dblclick` | click's fields without `clickCount`, which is refused here | Two presses in one gesture, so the page sees click, click, dblclick |
| `hover` | `ref` or `selector`, optional `position`, `force`, `timeoutMs`, `label` | Move the pointer onto a control and leave it there |
| `fill` | `ref` or `selector`, `value`, optional `append`, `timeoutMs`, `label` | Replace input, textarea, select value, or editable text, or add to it |
| `select` | `ref` or `selector`, `values` (0 to 100), optional `timeoutMs`, `label` | Choose a select's options by value, label or index; an empty array clears it |
| `press` | `key`, optional `ref` or `selector`, `delayMs`, `timeoutMs`, `label` | Press a key name, a printable character or a chord, optionally targeting a control |
| `scroll` | `direction`, optional `pixels`, optional `ref` or `selector`, optional `label` | Scroll the page, the panel holding a control, or the panel in the middle when the page cannot scroll |
| `drag` | `source` and `target`, each `{ "ref" }` or `{ "selector" }`, optional `sourcePosition`, `targetPosition`, `button`, `force`, `timeoutMs`, `label` | Drag the source onto the target with the mouse or HTML drag and drop |
| `mouse-click` | `x`, `y`, optional `button`, `clickCount`, `delayMs` | Click a viewport point without resolving a target; it takes no `label` |
| `wait` | `selector?`, `text?`, `timeoutMs?` | Wait for a visible element, text, or both |
| `navigate` | `url`, `waitUntil?`, `timeoutMs?`, `referer?` | Load an http, https or about:blank address and wait for the new document |
| `reload` | `waitUntil?`, `timeoutMs?`, `ignoreCache?` | Reload the page and wait for the new document; `ignoreCache` fetches past the cache |
| `wait-for-url` | `url`, `waitUntil?`, `timeoutMs?` | Wait for this page's URL to match a glob, then for the state asked for |
| `wait-for-load-state` | `state?`, `idleMs?`, `timeoutMs?` | Wait for the document the page shows to reach a state |
| `wait-for-selector` | `ref?` or `selector?`, `state?`, `timeoutMs?` | Wait for an element to be attached, visible, hidden or detached |
| `wait-for-function` | `expression?` or `function?`, `arg?`, `intervalMs?`, `timeoutMs?` | Wait for agent code to return a truthy value in the page |

Element actions wait until their target can take the input: `click` and `dblclick` for a visible, enabled element that receives the pointer at its point, `hover` and `drag` for one that also holds still, and `fill`, `select`, `focus` and a targeted `press` for a visible, enabled one. The wait lets the space's other requests run between attempts and goes on until `timeoutMs`, 3,000 ms by default and 0 to 60,000 ms, where 0 looks once. A selector that never matched ends as `422 no_match` with `waitedMs`; anything else ends as `504 action_timeout` with `awaited: "actionable"` and the last `blocker`: `no_match`, `detached`, `hidden`, `disabled`, `read_only`, `not_focused`, `moving`, `covered`, `outside_viewport`, `option_missing` or `frame_not_ready`. Each carries a `detail` sentence, and `covered` carries `interceptor`, the element in the way as `div#consent.banner "Accept all"` or `dialog "Sign in"` for an open modal. Read the blocker before acting again: a `covered` target needs the overlay gone, `disabled` needs whatever enables it, and `option_missing` needs an option the select really has. `force` skips the pointer and stability checks on `click`, `dblclick`, `hover` and `drag`, and never the visible or enabled checks. Up to six trusted wheel gestures, then one scroll from the page, bring a target on screen; `fill`, `select` and `focus` never scroll. After an action's first press nothing is sent twice: a cover found before a later press of the same gesture answers `409 element_obscured` with the `presses` made, and every error after that press carries `dispatched: true`. `fill` is the one action that tries again after its own input: a field that kept its old value gets one real click and one more round, then answers `422 fill_not_accepted` with the `match` it saw. A field with nothing to type into answers `422 not_editable` with a `reason`, a `select` with no select at the target `422 not_selectable`, a `focus` with nothing focusable `422 not_focusable`, and retargeting that finds several candidates `422 ambiguous_field` with them listed.

Every element action takes `label`, a few words naming the step in at most 60 characters: `--label "Open the details"` anywhere in a `click`, `dblclick`, `hover`, `fill`, `select`, `focus`, `press`, `scroll` or `drag` command's arguments, and a `label` field on those batch steps. The person sees it beside the agent's cursor and under the space's name while the action runs and for five seconds after it ends, and it stays on the action's activity entry. `snapshot` and `wait` steps, the `mouse-click` step, the mouse and keyboard commands and the observation commands take no label and refuse one with `400 unknown_field`, and a batch checks every label before its first step, naming the step in `index`. Keep field values, secrets and personal data out of labels.

Compact snapshots default to 4,000 text characters and 40 controls. Full snapshots default to 24,000 characters and 100 controls. Hard bounds are 0 to 24,000 characters and 0 to 100 controls. `--full` increases the budget while keeping concise text output. `--max-chars` and `--max-controls` override budgets; use zero controls for reading-only tasks. Check `truncated` before assuming a snapshot covers everything needed. When controls exceed the budget, open dialogs, popups, listboxes and menus come first, then fixed or sticky bars on screen, then the rest of the screen, then tall pinned columns such as a navigation sidebar or table of contents, then everything else. `omittedControls` counts the controls left out, and text output says how many more exist. Besides native controls, snapshots list ARIA options, menu items, tabs and switches, focusable custom elements, and a few clickable elements without control semantics, which show their tag as the role, such as `div`.

Refs such as `@e4` remain tied to the same element and document and are not reused for a different target. Navigation or a change of URL makes them stale. When the page replaces the element with one that has the same tag, role, type, label, group question and surrounding text, at the same place in the page or as the only match, the ref follows it and the result lists it in `rebound`; text output says the ref now points to the redrawn control. An ambiguous or missing match fails with `stale_ref`, and so does a control that looked like another visible control when it was listed. File-input refs never follow a replacement. Selectors take any form [Selectors](#selectors) lists and must name one element the action can take. Fill accepts text and date/number input types, textareas, single selects and contenteditable text, and sets range and color inputs directly. It rejects file, checkbox and radio inputs; use click for checkboxes and radios and `upload` for a file input. A fill of a single select must match exactly one enabled option outside a disabled option group, while `select` chooses by value, label or index and takes a disabled option too. Use option values shown in snapshots. Multiple selects and values Chromium would silently normalize are rejected. Controls show `checked` (`true`, `false` or `"mixed"`), `selected`, `expanded` and `pressed` where they apply, the current `value` of fields, selects and editable text, and `group`, the question a radio button or checkbox answers. Text output shows these as `[checked]`, `[unchecked]`, `[mixed]`, `[selected]`, `[expanded]`, `[collapsed]`, `[pressed]`, `value="..."` and `group "..."`. Password, one-time code and card fields show `valueHidden` or `(value hidden)` instead, but ordinary page text can echo their values. Page text includes rendered text inside `aria-hidden`, where component libraries put visible labels; controls inside it are not listed. Select options are bounded to 20 per control and 100 per snapshot; oversized values are omitted and `truncated` is set. Field values are limited to 16,384 characters and selectors to 2,048 characters.

Drag presses on the source's center, moves in steps past the distance pages wait for, and releases on the target's center with native mouse input. `sourcePosition` and `targetPosition` act at a point of their own inside each element, `button` drags with another button, `force` skips the pointer and stability checks, and `timeoutMs` bounds the wait for both ends, which are measured together so a blocker names the end it belongs to. An HTML drag the page starts is carried with drag events and dropped on the target. The result says `drag: "html5"` or `drag: "mouse"`. Both elements must be visible and fit on screen together; elements that cannot both be there fail with `drag_out_of_view`, and another element over the target after the press fails with `element_obscured`. Check the page afterwards, since many lists commit a new order only when the drag ends. A click on a control drawn with no size, such as a radio button in a list row, falls back to a click in the page and reports `fallback: "dom_click"`; it never falls back when the control is covered or off screen.

`press` takes any key of the US layout: `Enter`, `Tab`, `Escape`, `Backspace`, `Delete`, `ArrowUp`, `ArrowDown`, `ArrowLeft`, `ArrowRight`, `Home`, `End`, `PageUp`, `PageDown` and `Space`, the rest of the layout such as `KeyA`, `Digit1`, `F12` and `Numpad0`, any printable character, and a chord of at most 6 tokens and 64 characters joined with `+`, such as `Shift+KeyA` or `ControlOrMeta+KeyS`. `ControlOrMeta` is Meta on macOS and Control elsewhere, names ignore case, characters keep it, and a `+` that starts a token is the key itself, as in `Control++`. The modifiers go down, the key's own down types its text and carries the standard macOS editing commands of that chord, `--delay <ms>` holds it, and everything is released in reverse. An unknown name answers `400 invalid_key` with a `suggestion`, such as `ArrowLeft` for `Left`, `Escape` for `Esc` or `Meta` for `Cmd`. Kamapathy never uses the system clipboard, so a copy, cut or paste chord answers `403 clipboard_blocked` before any key is sent, held modifiers included, as does a middle press over an editable on Linux; paste with `paste TAB_ID --stdin` instead. Input that would open a native select, color or date picker answers `403 native_popup_blocked` with the `use` to try instead, and a point or a focused frame inside an extension, the PDF viewer or an internal page answers `403 input_target_blocked`, even with `--force`. Agent keys never run Kamapathy's own shortcuts or menu roles, and an agent right click opens no native context menu. Scroll pixels default to 600 and range from 1 to 2,000. A scroll result reports `scrolled` (`page` or `element`), the scrolled element's `selector`, its new `x` and `y`, and `moved: false` when nothing could scroll further. A page locked behind a modal never scrolls. Wait timeouts default to 5,000 ms and range from 0 to 15,000 ms. With both selector and text, the text must occur inside the selected element, and text never matches across a frame boundary. Use observable waits instead of arbitrary sleep delays.

Navigation and the waits share one state and one timeout model. `waitUntil` and `state` take `commit`, `domcontentloaded`, `load` or `networkidle`, where `domcontentloaded` waits for the page's own handlers to finish and `networkidle` waits for the load event and then for `idleMs` (500 by default) with nothing in flight. A `navigate` or `reload` step waits 1 to 60,000 ms, 15,000 by default, and answers with the tab, the state it reached and the document's `httpStatus` when one arrived; without `waitUntil` a step waits for `load`, while the `navigate` command and `page.navigate(url)` return at commit. A wait step waits 0 to 60,000 ms, 10,000 by default, and 0 checks once. A `wait-for-url` step takes a glob: `*` stops at a `/`, `**` crosses segments, `/**/` may match nothing, `{a,b}` holds one level of alternatives, a backslash escapes the next character, and a plain URL is compared normalized; a RegExp or a predicate works in a script only. `wait-for-selector` takes any target below, with `attached` and `visible` naming one element as every action does while `hidden` and `detached` count every match. `wait-for-function` runs code of yours in the page, so it needs the Page scripts setting on, as [page-scripts.md](page-scripts.md) describes, and `reload` with `ignoreCache` runs no page script and is not gated by it. A tab accepts four navigations and waits at once; a fifth answers `429 busy` with `scope: "tab"`. In a batch, each step's `timeoutMs` is cut to what is left of the 60-second budget, and the whole plan, globs included, is checked before the first step runs.

A navigation that never loads a document answers `422 navigation_failed` with the `url`, the `netError`, the `errorCode`, any `httpStatus` and `blockedUrl` for a redirect to an address agents may not open; only six network errors make it retryable. `422 navigation_download` means the address is a download, `409 navigation_interrupted` that a newer navigation replaced this one, `409 reload_would_resubmit` that reloading would send the page's form again, and `504 navigation_timeout` carries `committed`, the `url` and the `readyState` it reached. A wait that is not met answers `504 wait_timeout` with `awaited` and what it last saw, and `409 url_opened_in_popup` says the URL opened in a popup this page opened: the action already happened, so continue in that page. A page's leave guard cannot keep an agent on a page: the page goes and the answer carries `dialog beforeunload accepted`, while the person in control is asked instead. An address agents may not open answers `400 invalid_url` with the `url` and often a `hint`.

Single-action equivalents include `click TAB_ID @e4`, `dblclick TAB_ID @e4`, `hover TAB_ID @e4`, `select TAB_ID @e4 pro`, `focus TAB_ID @e4`, `press TAB_ID ControlOrMeta+KeyS @e4`, `drag TAB_ID @e4 @e9`, `scroll TAB_ID down 600`, `scroll TAB_ID down 600 @e9`, and `wait TAB_ID --stdin` with JSON options. Each of those but `wait` also takes `--label "<text>"` anywhere in its arguments. A single fill takes raw text through stdin, whereas batch values are JSON strings. The client preserves fill input exactly, including trailing newlines. When a single command fails, the CLI prints `Kamapathy: <status> <code>: <message>`, then `Kamapathy: Nothing reached the page, so the same command can be retried.` for a retryable error or `Kamapathy: The action reached the page before it failed. Inspect the page before retrying.` for one that reached the page. Retry only after the first.

## Mouse and keyboard

When no ref names what a task needs, as on a canvas or a custom widget, drive the tab's own mouse and keyboard. Each agent tab has one input state in Kamapathy, not in the page: the pointer's position, which starts at 0,0, the buttons and keys it holds and the modifier mask. The mouse and key commands answer with that state as `input: { x, y, buttons, keys, modifiers }`, so text output prints `ok: mouse at <x>,<y> buttons <n>`, `ok: keys <names>` or `ok: no keys held`; `insert-text` and `paste` answer without it, and `release-input` names what it let go. These commands resolve no target and check no actionability, so verify the result on the page yourself.

| Command | Script | Behavior |
| --- | --- | --- |
| `mouse-move TAB_ID X Y [--steps <n>]` | `page.mouse.move(x, y, { steps })` | Move to a point, interpolating 1 to 100 steps from where the pointer stands |
| `mouse-down TAB_ID [--button <b>] [--click-count <n>]` | `page.mouse.down({ button, clickCount })` | Press a button where the pointer stands |
| `mouse-up TAB_ID [--button <b>] [--click-count <n>]` | `page.mouse.up({ button, clickCount })` | Let a held button go there |
| `mouse-click TAB_ID X Y [--button <b>] [--click-count <n>] [--delay <ms>]` | `page.mouse.click(x, y, options)`, `page.mouse.dblclick(x, y, options)` | Move to a point and click it, with the receipt and settle an element click gets |
| `mouse-wheel TAB_ID DELTA_X DELTA_Y` | `page.mouse.wheel(deltaX, deltaY)` | Scroll where the pointer stands, with deltas within 10,000 px |
| `key-down TAB_ID KEY` | `page.keyboard.down(key)` | Hold one key, so later input carries it |
| `key-up TAB_ID KEY` | `page.keyboard.up(key)` | Let one held key go |
| `press TAB_ID KEY` | `page.keyboard.press(chord, { delay })` | A press with no target, where the focus is |
| `type TAB_ID --stdin [--delay <ms>]` | `page.keyboard.type(text, { delay })` | Type up to 2,000 characters as key events |
| `insert-text TAB_ID --stdin` | `page.keyboard.insertText(text)` | Put up to 16,384 characters at the focused editable's caret; `422 not_editable` when nothing editable has focus |
| `paste TAB_ID --stdin [--html]` | `page.keyboard.paste(text \| { text, html })` | Offer the focused element a paste in a transfer of its own |
| `release-input TAB_ID` | `page.releaseInput()` | Let go of every key and button the page holds, and report them |

Coordinates are viewport CSS pixels of the top document, the same space snapshots and CSS-scale screenshots use, so a point read from a snapshot or a capture lands where it looks. A point outside the viewport answers `422 point_outside_viewport` with the viewport's `width` and `height`; `GET /tabs/:id/info` gives that size. A wheel delta goes out as one event up to 100 px, else as up to ten eased events that sum exactly.

A paste never touches the system clipboard. Kamapathy builds a `DataTransfer` of its own with the text and, with `--html`, the HTML given as a JSON object `{ "text": "...", "html": "..." }` on stdin, and dispatches a cancelable `paste` event at the focused element. A handler that takes it answers `handled: "page"`; otherwise Kamapathy inserts the plain text and answers `handled: "text"`, and it never inserts the HTML itself.

Held keys and buttons are let go on a cross-document navigation of the main frame, after 60 seconds without an input request from the tab, and on `release-input`, which a `run` sends for every page it touched when the script ends. A takeover, a Stop and agent access going off release the keys alone, so a drag in progress is never dropped halfway. Release what you hold before you finish a task, so no page is left with a key or a button down.

## Selectors

Every target takes one grammar, in a batch step and in a single command alike, at most 2,048 characters. `help selectors` prints it.

| Form | Example | Matches |
| --- | --- | --- |
| Ref | `@e12` | Its snapshot element; no search |
| CSS, the default | `form .save` | CSS in the document and in each open shadow root, each tree alone |
| `css=` | `css=#save` | The same |
| `text=`, unquoted | `text=sign in` | Innermost elements whose text contains it, ignoring case and extra spaces |
| `text=`, quoted | `text="Sign in"` | Elements with an own text run equal to it |
| `role=` | `role=button[name="Save"]` | Chromium's computed role with that exact accessible name; `[name*="pri"]` takes part of the name, ignoring case, and `role=checkbox` takes any name |
| `href=` | `href=/plans?tier=pro#faq` | Links whose path, query and hash, or whose whole URL, equals it |
| `xpath=`, or a leading `//` or `..` | `xpath=//table//tr[2]` | Elements from `document.evaluate` in each document, never in a shadow root |
| CSS ending in `:has-text("...")` | `li:has-text("Invoice 12")` | CSS matches whose text, shadow content included, contains it, ignoring case |
| CSS ending in `:text-is("...")` | `button:text-is("Save")` | CSS matches with an own text run equal to it |
| Any form but a ref, ending in `>> nth=N` | `role=button[name="Delete"] >> nth=-1` | The Nth match in search order, from 0; -1 is the last |

`selector: "@e12"` acts as the ref. The search covers the top document first, then each frame's document, from any web origin, depth first in the order their owners sit on the page and a frame's document before the frames inside it. It never searches a blocked frame, and within a document it follows what a person sees, with a host's open shadow content before its light children. When the top document holds a match the action can take, it decides alone; otherwise the matches in every frame count together, and `>> nth=N` counts document by document in this order. Matches split across frames from different origins answer `ambiguous_match` with no `candidates`, so take a snapshot and act on a ref. `role=` reads Chromium's computed role and accessible name, so `button` also matches `summary` and a color or file input, `textbox` also matches a contenteditable region and date and time inputs, and `table`, `row` and `cell` also match a table of `td` cells without headers. An exact name is Chromium's name as it stands, which keeps U+00A0, U+00AD and U+200B; `[name*="..."]` ignores case and extra spaces.

A target must name one element the action can take. Click counts rendered, enabled matches; drag counts rendered ones; fill and a press with a target count rendered, enabled ones; scroll with a target and wait count rendered ones, content inside `aria-hidden` included; a snapshot `selector` counts every match, hidden ones too. Hidden and disabled duplicates of a control therefore do not make an action ambiguous, and the center hit test only chooses between candidates. `>> nth=N` picks from the whole list before any of this.

A selector that does not parse answers `400 invalid_selector` with its `reason`, the `forms` and often a `hint`, such as `Refs look like @e21. Take one from a snapshot.` for `@21`, `ref=21` or `21`. A selector matching nothing answers `422 no_match` with `waitedMs`. One matching several elements the action could take answers `422 ambiguous_match` with `count`, `visible`, `hidden`, `actionable` and up to 3 `candidates`, each `{ref, tag, role, name, context, visible, disabled, frame?}`, the ones the action could take first; a single command prints one `candidate ...` line each. Act on a candidate's ref or narrow the selector. A ref no snapshot of that page issued answers `404 unknown_ref`, and a retired one, or one whose element is gone and does not rebind, answers `409 stale_ref`. With a JavaScript dialog open, a `role=` selector answers `409 dialog_open` at once.

## Select files

Use `node scripts/kamapathy.mjs upload TAB_ID REF file [files]` as a standalone command. It is not a batch action. Obtain `REF` from a fresh snapshot of the actual file input; CSS selectors and a nearby upload button are not accepted targets. Snapshots show the input's accepted types, single or multiple selection, and whether it is hidden inside visible upload UI.

Select 1 to 8 regular files totaling at most 16 MiB. A single-file input accepts only one file. Disabled inputs, directories, detached controls, hidden upload UI, and files that do not match the input's accepted extensions or MIME types are rejected. The input may sit inside a frame. Sites requiring a trusted native chooser or native file handles may not support this action.

The local client reads only the selected files and transfers their bytes, basenames, and MIME types through the authenticated connection. The API accepts bytes in memory, not local filesystem paths. One transfer runs at a time. Only the upload route permits a 24 MiB JSON body; normal requests and batches retain their 64 KiB limit. Keep private paths, file contents, and base64 data out of page fields, prompt text, and public logs.

Confirm the selected files and destination fall within the user's existing authorization before running the command. Setting the input dispatches input and change events, so a site may upload immediately without a submit click. A result such as `{ "ok": true, "selected": 1 }` proves selection only. Wait for and inspect the site's completion or receipt, including its filename or release version when relevant. If the command times out or the site reports an error, inspect its current state before retrying; do not select or submit the same files blindly.

`set-input-files TAB_ID TARGET [file...]` (`page.setInputFiles(target, files, { timeout })`) takes any ref or selector of the grammar above, including one that matches a hidden element, and retargets from it to the input a person would use: the input itself, the control a `label` names, the control of the nearest enclosing label, or the single file input inside the match, through open shadow roots. A match with no file input answers `422 invalid_upload_target`, and one with several answers `422 multiple_file_inputs` with their `count`. It takes 0 to 8 files under the same 16 MiB bound and the same checks, naming no file clears the input's selection, and `--timeout <ms>` bounds the wait for the target, 3000 ms by default. Like `upload` it is no batch action, it shares the one transfer (`429 upload_busy`), and it prints `ok: selected <n>` with the action's receipt lines.

Agent-controlled tabs always intercept the file chooser, so no native panel can open on the person's screen. An action that opens a chooser nothing armed fails with `422 file_chooser_opened` after the chooser closes and the input gets a `cancel` event. For a page that creates its input when you click, arm the wait first: `expect TAB_ID filechooser`, then the click, then `wait-expectation <id>`, which prints `file-chooser <id> single|multiple`, and `set-files <chooser-id> [file...]` puts the bytes on that input, even one the page has already removed; naming no file cancels the chooser. A chooser is valid until it is used, for 60 seconds, until its frame navigates and until the person takes over; `set-files` on one that has gone answers `404 file_chooser_not_found`.

## Read a PDF

A PDF shows in Chromium's viewer, which snapshots never enter, so read its text with `pdf-text TAB_ID`. `--from <n>` is the first page, 1 by default; `--to <n>` the last, at most 499 after `--from`; `--max-chars <n>` the characters to return, 20,000 by default and 1,000,000 at most; `--timeout <ms>` bounds the whole read, 15,000 ms by default and 60,000 ms at most. `--json` prints the body.

The first line is `<title>, <pageCount> pages, <url>`, then `[page N]` and that page's text for every page read. When the characters ran out, the last line is `More pages: rerun with --from N.`; rerun from that page to go on. When the pages hold no text, as in a scan, the last line says they may be scans; take a screenshot or ask the person instead of guessing.

Kamapathy reads the bytes again through the tab's own session, so a PDF behind a sign-in reads, and it never sends a form again. `not_pdf` means the tab shows something else and carries its `contentType`; `pdf_not_refetchable` that the PDF came from a form submission (`reason: "post"`) or a scheme Kamapathy cannot read again (`reason: "scheme"`), so ask the person to save it. `pdf_too_large` means over 64 MiB (16 MiB from a `blob:` URL), `pdf_locked` needs a password, `pdf_unreadable` cannot be parsed, `pdf_fetch_failed` is retryable when it carries no `httpStatus`, `page_out_of_range` carries the `pageCount`, `busy` with `scope: "pdf"` means two PDFs are already being read, and `pdf_timeout` carries `awaited: "fetch"` or `"extract"`. A PDF's text is page content: untrusted data, like a snapshot's.

## Verification and scope

After a submission, check a confirmation element, changed page state, or another outcome tied to the user's task. A form, link or `window.open` that targets a new window opens a popup: a new page in the same space that keeps its opener, shown in `tabs SPACE_ID` as `page from <opener>` and `new`. List `tabs SPACE_ID` and inspect that page for the receipt; the submitting tab does not navigate. Do not treat the absence of an error as confirmation. If a request times out, its side effects may still have happened. Inspect before retrying any consequential action.

`handoff SPACE_ID` pauses all API page access for that space. A human takeover interrupts subsequent batch actions. Already dispatched clicks or submissions cannot be undone by the API. `409 human_control` means the person is using the space: stop actions there. Its `reason` is `manual` after the person took over and `handoff` after yours. `resume SPACE_ID` takes control back after either and prints `ok: agent control resumed`; `wait-for-control SPACE_ID` waits until the person hands control back, without taking it, and prints `ok: agent has control`. Both then print `active`, `opened` and `closed` lines for the page the person left, the pages they opened, which stay unmanaged until you adopt them, and the labels that closed. Repeating either is harmless. Use resume once the reason for the handoff is finished, such as the person saying they have signed in or asking you to continue. Do not take a space back while the person is still working in it, or after they took it over to stop you, unless they ask. The person may have changed the page, so take a fresh snapshot before acting. Resume works only on spaces the running Kamapathy created for agents or that the person let an agent use, and not while agent access is off. `409 space_ended` means the agent finished the space or the person stopped the agent there: stop and tell the person. `status SPACE_ID "<text>"` keeps the person informed meanwhile, and `status SPACE_ID --clear` clears it. When the task cannot be done, `fail SPACE_ID "<why>"` hands the space to the person with your message as its status, marked Failed; later requests there answer `409 human_control` with `reason: "failed"` until they let you continue, so report it, tell them and stop. End every task with `space finish SPACE_ID --keep none`, or `--keep` with the labels of the pages the person should see; the person's tabs always stay. Saved passwords belong to the person. Kamapathy never fills them for you or says which exist. When a site needs a password you were not given, hand off and say what to sign in to; never ask for a password in the conversation.

Snapshots read through open shadow roots and frames from any web origin, nested ones included, and clicks, fills, key presses, drags, uploads and waits work on what they list there. A control inside a frame carries `frame`, its frame's index path. A frame from another origin is also an `iframe` entry with `crossOrigin: true`, which now means its origin differs from the document around it, and with `origin`, `contentFrame`, the `frame` path its controls carry, and `content`: `read`, `pending` while it attaches or loads a document, `unavailable` when it was silent for 2 seconds or could not be reached, `limit` past 32 frames from other origins or 8 levels of them in one read, or `blocked`. `unreadFrames` counts the frames left `pending`, `unavailable` or `limit`, on a snapshot and on a `no_match`, `action_timeout` or wait timeout: snapshot again shortly, or pass an entry's ref as `--root` to read that frame's document alone. A snapshot of a page with frames is cut into parts as one document's is: an outline prints an open dialog first and repeats the ancestors of a continued part's first line, and `next` keeps coming while any frame still has controls or lines to print. A frame from another origin narrower or shorter than 4 CSS pixels, such as a tracking pixel, is left out. A ref inside a frame goes stale when its frame loads another document or is removed, and `stale_ref` then carries `frame`; refs in the top document are unaffected. An action whose frame is attaching, loading another page or silent waits on the blocker `frame_not_ready`, and an action in a frame from another host ends its activity entry with `in a frame from <host>`. `409 cross_origin_frame` is retired: no route returns it, and actions work inside those frames instead. Extension, PDF viewer, internal, local file and Kamapathy frames, and everything inside them, are never read or reached: their entries say `content: "blocked"` and carry no `origin`. A frame of one of the person's extensions is an `iframe` entry with `extension` and the label `Extension: <name>`, is never read, and fails a click, key press or paste with `input_target_blocked`, carrying `frame` and `extension`, so ask the person to continue in the extension; their extensions run in agent spaces that share their sign-ins, never in an isolated one. A selector searches the top document first and then its frames, and a control inside a frame lists a selector of its own document, which may match in the page around it too, so prefer its ref or a locator. CSS searches each open shadow root on its own, and XPath never enters one. Snapshots do not enter closed shadow roots, and a PDF is read with `pdf-text TAB_ID` instead; a canvas has no controls to list, so it is worked with the tab's mouse and keyboard. A screenshot file holds the viewport, or the whole scrollable document with `--full-page`, or one region with `--clip x,y,width,height`, in CSS pixels unless `--scale device` asks for device pixels; the Kamapathy window may be hidden or minimized. Your own scripts and protocol commands run only through the calls in [page-scripts.md](page-scripts.md), only in your tabs and only while Page scripts is on, and page.cdp reaches only the agent tab's own page and frames; a personal space is reachable only after the person lets an agent use it. A JavaScript dialog in your own tab is answered by Kamapathy's fixed handler with no box on the person's screen, dismissed unless `dialog-policy TAB_ID accept` armed an accept before the action, and reported in the action's answer and in `dialogs TAB_ID`; one Kamapathy could not answer leaves that tab's requests failing at once with `409 dialog_open`, which names it, and only the person can close it. A page whose process stopped returns `409 page_crashed` until it loads again.
